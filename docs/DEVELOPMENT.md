# 개발 기준 · v0.6

- PC 키보드·마우스와 한 키보드의 로컬 2인 대전·협동을 기준으로 한다. 모바일 레이아웃과 가상 조작 버튼은 제외한다.
- 순수 HTML/CSS/JS와 네이티브 ES Module을 사용한다. 외부 라이브러리·CDN·게임 자산·서버 API를 추가하지 않는다.
- 실행 원본 합계를 1,000,000바이트 미만으로 유지한다. ZIP·문서·테스트 용량과 구분한다.
- 게임마다 진입 모듈을 유지하고 실제 중복만 공유한다. 들여쓰기는 공백 4칸, 짧은 도우미는 화살표 함수로 작성한다.

## 구조

`app → catalog → games`를 기본으로 한다. `core`는 입력·시계·예약 작업·DOM/Canvas·준비·종료 수명주기를 제공한다. `rules`는 브라우저 상태가 없는 순수 규칙이며 `hexLayout`은 실제 판과 로고의 기하를 함께 정의한다. `effects`는 충돌 판정에 관여하지 않는다.

`connection-game`은 틱택토·오목·사목의 배치·승리·복원만 공유한다. 게임 사이의 직접 의존은 만들지 않는다. 번들 진입점은 `js/app.js`, 정적 import만 사용한다.

## 시간과 수명주기

`session.time`, `session.elapsed()`, 물리 갱신, `session.later()`는 하나의 활성 시계를 사용한다. `startClock()`은 해당 게임의 기록 시작점을 바꾼다. 최초 준비 완료 이후의 라운드 준비는 경기 시계를 초기화하지 않는다.

활성 프레임은 최대 1/60초 단위로 나누어 처리한다. 0.75초를 넘는 프레임 중단은 시계를 진행시키지 않고 자동 일시정지한다. DOM 퍼즐도 활성 시계를 진행하지만 불필요한 화면 재생성을 하지 않는다. 준비·일시정지에서는 RAF를 중단한다.

입력 리스너는 `session.on`, 게임 키는 `session.bindKeys`를 쓴다. 키패드 숫자와 Enter를 일반 숫자·Enter에 대응시킨다. 네이티브 버튼·입력 필드·열린 dialog의 키 작동을 보호한다. 준비 화면 아래의 보드는 `inert`로 가린다.

`finish()`는 승패·점수·기록 시간을 즉시 확정하고 입력·예약 작업·게임 갱신을 차단한다. `afterFinish()`가 있으면 파티클만 0.22초간 진행한 뒤 결과 콜백을 보낸다. 모션 줄이기 설정에서는 즉시 결과를 보여준다. 이 구간은 기록에 더하지 않는다. 전환·파괴 시 남은 프레임과 콜백도 취소한다.

## 조작과 진행 보호

`session.controls`는 게임 고유 도구만 생성한다. 도구 동작 후 진행 중일 때만 게임으로 포커스를 돌린다. 종료한 동작 뒤에는 결과 버튼 포커스를 덮어쓰지 않는다. 동적 표시 모드는 보이는 텍스트·`aria-pressed`·툴팁을 함께 갱신한다.

의미 있는 실제 입력에서 `session.changed()`를 호출한다. 퍼즐·기억·턴제 게임의 초기화·모드 변경·목록 이동은 dirty 상태에서 확인창을 거친다. 취소하면 진행과 기존 일시정지 상태를 복원한다. 브라우저 종료 경고는 추가하지 않는다.

결과 보기는 보드를 `inert`로 막는다. 살펴보기에서는 `inert`를 풀되 `aria-disabled`와 게임 종료 상태로 편집을 막고 방향키 탐색은 허용한다. 다음 문제가 있으면 그 버튼이 기본 동작이다.

`history`는 게임이 선택한 상태만 복제·복원한다. 보드 대전의 되돌리기는 돌·차례·점수·추가 턴을 함께 복원한다. 싱글플레이 보조는 `session.assist()`로 최고 기록 자격을 구분한다.

## 문제와 기록

슬라이딩·Lights Out·Flood·미로·블록 묶음 지우기는 정수 시드로 재현한다. `R`은 같은 시드, `N`은 새 시드다. 앱은 모드별 마지막 시드를 보관한다. 이 난수는 게임 생성용이다.

슬라이딩·Flood 기록은 모드와 시드로 나눈다. Lights Out은 시작 최적해보다 더 쓴 이동 수를 작을수록 좋게, 미로는 최단 경로 대비 효율을 클수록 좋게 비교한다. 정수 시간 퍼즐은 소수 초를 버리고 최소 1초, 스프린트는 0.1초 단위로 표시·기록한다. 해당 완료 결과에도 같은 값을 넘긴다.

기록 키는 `game:v3:variant`다. 이전 데이터는 삭제하지 않는다. 로직 퍼즐의 완료 여부는 clean/assisted로 구분하고 clean을 assisted로 낮추지 않는다. 잘못된 최상위·중첩 데이터, 숫자 필드와 개별 기록을 정상화한다. 저장 실패는 실행 중 기록으로 표시하며 성공 문구를 쓰지 않는다.

## 표현과 확인

남은 창 높이는 앱이 실제 패널 여백·HUD·도구를 측정해 `--surface-height`로 넘긴다. 보드는 열/행 비율, Canvas는 논리 비율을 유지한다. Canvas의 DPR은 최대 2이며 물리 좌표와 표시 크기를 분리한다.

SVG는 공통 140×112 필드와 도형 도우미를 사용한다. P1/P2 색과 구조선의 강도를 맞춘다. 불필요한 문자 그림·플랫폼 이모지로 공통 아이콘을 대체하지 않는다. HUD 수치 전체를 라이브 알림으로 보내지 않고 안내 문구만 상태 알림으로 쓴다.

변경 시 관련 규칙·실행·회귀 검사를 실행한다. 자동 검사의 DOM 어댑터는 실제 레이아웃·브라우저 포커스·스크린리더를 대체하지 않으므로 PC 화면에서 필요한 경계를 별도로 확인한다. 새 테스트는 수정한 실패 조건과 실제 입력 결과를 확인하며 구현 문자열을 복제하지 않는다.

검사 명령과 한계는 README, R01~R28 대응은 [QUALITY-v0.3.md](QUALITY-v0.3.md), 바이트 집계는 [SIZE.md](SIZE.md)를 참고한다. 최종 단일 HTML은 사용자가 만든 뒤 별도로 실행·외부 요청·크기를 확인한다.

## v0.4 게임별 계약

신규 게임은 `sokoban.js`, `samegame.js`, `wall-race.js`, `tanks.js`의 독립 진입점으로 둔다. 격자 이웃·상자 이동·블록 붕괴·장벽/점프/경로·탄환 경로 판정은 `rules.js`의 순수 함수로 검증한다. 소코반 데이터는 `puzzles.js`, 탱크 경기장은 해당 게임 모듈이 소유한다.

`grid.focus(i)`는 보드의 단일 Tab 진입점을 바꾼다. 실제 키보드 포커스 이동은 필요할 때 셀의 `focus()`로 수행한다. 소코반은 플레이어 위치를 진입점으로 유지하며, 자동 걷기와 예약한 방향은 일시정지 때 취소한다. 되돌리기 이력은 수 제한을 두지 않고 스테이지 전환 시 정리한다.

블록은 제거·낙하·열 당김을 활성 시계의 예약 작업으로 순서대로 진행한다. 전환 중 추가 제거를 막고 `aria-busy`를 표시한다. 모션 설정은 공통 `reducedMotion()`으로 읽으며, 모션을 줄인 새 동작은 연출 대기를 생략한다.

장벽의 포인터 좌표는 보드의 테두리를 제외한 영역으로 환산한다. 말·장벽·목표선은 동일 격자를 사용한다. 셀의 접근성 이름에 도착선과 막힌 방향을 제공한다. 장벽 확정 전에 두 사람 모두 목표에 도달할 길이 있는지 검사하며 되돌리기는 장벽·재고·차례를 함께 복원한다.

탱크의 탄환은 한 갱신 구간의 충돌 지점까지 이동한 후 남은 시간으로 반사 경로를 계산한다. 플레이어 이동을 반영한 연속 충돌을 검사하고 같은 틱의 격파를 함께 처리한다. 발사 전에 포구 경로가 막혔는지 확인한다. 준비 카운트다운을 소비하고 남은 dt만 게임 진행에 쓰며 타이머의 부동소수점 경계를 정규화한다.

소코반의 `tieScore`는 기본 밀기 점수가 같을 때 비교하는 이동 수다. 저장된 `bestTie`는 음수가 아닌 안전한 정수만 허용한다. 기존 v3 기록 키는 유지한다. `progress` 메타데이터는 소코반·로직 퍼즐의 완료 선택·집계를 공유하며 소코반 완료 키는 `sokoban:stage-N`, 기존 로직 키는 `puzzle-N`이다.

신규 구현의 검사는 `tests/new-games.mjs`에서 독립 최소 밀기 탐색, 실제 입력, 모의 프레임 간격, 완료·기록·정리를 확인한다. 브라우저 RAF 제한에 관한 실제 관측과 검증 한계는 [QUALITY-v0.4.md](QUALITY-v0.4.md)에 기록한다.

## v0.5 게임별 계약

게임 진입점은 `territory.js`, `bubbles.js`, `golf.js`, `switch-duo.js`다. 별도의 프레임워크나 자산 모듈은 추가하지 않는다. 격자 점령·버블 이웃/연결/연속 경로·골프 물리·협동 의도 해결은 `rules.js`, 코스와 협동 스테이지는 `puzzles.js`에 둔다.

버블의 조준과 실제 발사는 `bubbleTrace`를 공유한다. 새 행 삽입 때 phase를 반전해 기존 버블의 x를 유지한다. 같은 틱에 제거와 고립 낙하를 확정한 후 연출 동안 입력을 잠근다. 다음 색은 남은 색에서만 고른다. 골프는 지수 마찰을 적분하며 충돌 후 잔여 시간도 처리한다. 공은 독립적이며 홀을 끝낸 플레이어는 차례를 건너뛴다.

협동 이동은 같은 틱의 두 의도를 현재 문 상태로 검사한 후 함께 확정한다. 같은 목적지는 취소하고 자리 교환은 허용한다. 발판·토글·문 위 점유로 열림을 결정한다. 걸음 수는 움직인 개별 플레이어마다 1씩 증가한다. 풀이 인증은 완료 가능성을 검증하며 최단 공동 해답을 주장하지 않는다.

카탈로그의 모드가 `players`/`record`를 덮어쓸 수 있다. 골프 solo는 1P/low, duel은 2P/duel이다. 인원 필터는 게임이 지원하는 모드의 합집합을 사용한다. `coop`는 협동 결과 문구, `protectProgress`는 골프와 협동의 진행 보호를 지정한다. 협동 완료 키는 `switch-duo:stage-N`이며 기존 키를 바꾸지 않는다.

`releaseKeys()` 뒤 자동 반복만으로 키를 다시 추가하지 않는다. Undo는 큐와 유지 입력을 함께 비운다. 탱크는 남은 탄환 수명으로 추적 시간을 자르고, 구간 시간은 원래 dt의 비율로 환산한 뒤 이동 플레이어와 검사한다. 6번째 반사 이후 구간은 피격 검사에서 제외한다.

`tests/expansion.mjs`는 실제 새 게임 입력·완주·실패·복원·모드 기록·완료·진행 보호를 검사한다. 세부 결과와 브라우저의 1fps 제한은 [QUALITY-v0.5.md](QUALITY-v0.5.md)를 참고한다.

## v0.6 계약

신규 진입점은 `laser.js`, `mancala.js`, `sudoku.js`, `pipes.js`다. 단일 규칙 함수는 `rules.js`, 고정 퍼즐은 `puzzles.js`에 둔다. 새로운 프레임워크나 별도 로더는 만들지 않는다. 레이저/파이프는 12판씩, 스도쿠는 18판이며 모두 기존 `progress` 완료 경로를 사용한다. 완료 키는 각 `game:stage-N`으로 기존 데이터와 분리한다.

세 퍼즐의 Undo는 기록 자격을 유지하고 힌트만 `assist()`를 호출한다. 스도쿠 Undo는 숫자와 자동 정리된 메모까지 복원하며 경과 시간을 되감지 않는다. 숫자 중복 표시만 제공하고 정답 대조는 힌트에서만 쓴다. 해답 존재·유일성은 별도 탐색기로 교차 확인한다.

레이저는 셀과 방향의 쌍을 한 번만 방문해 분기·중첩·순환에서도 유한하게 끝난다. 반복 방문 안내는 경로 중첩도 포함하며 실제 순환으로 단정하지 않는다. 파이프의 완료는 모든 칸이 전원에 이어지고 모든 포트가 맞물리는 두 조건을 모두 만족해야 한다. 회전 표현은 기존 DOM 노드를 유지하고 회전 누적 값을 상태와 함께 되돌린다.

만칼라는 실제 동작 전에 순수 `mancalaMove` 결과를 계산한다. 씨앗 배분 중 입력과 Undo를 잠그고 마지막에 포획·종료 정산·차례를 확정한다. 배분 시각은 해당 수의 시작 시각을 기준으로 예약해 짧은 대기 오차가 누적되지 않게 한다. 중간에도 보드와 손에 남은 씨앗 합은 일정하다. 종료는 추가 턴보다 먼저 판정하며 Enter 반복 입력으로 다음 수를 자동 실행하지 않는다.

`pauseOnStall` 기본값은 true다. 기존 게임과 짧은 미리보기는 프레임 중단 보호를 유지한다. 새 네 게임만 false로 설정하며, 물리나 반응 제한 시간이 없어 활성 시계·예약 작업을 진행할 수 있다. 사용자 pause·blur·visibility 처리는 별도이며 계속 적용한다. 이 정책을 반응 속도 게임에 그대로 복사하지 않는다.

`tests/logic-pack.mjs`는 독립 규칙 모델, 모든 신규 퍼즐의 입력 완주, 공동 Undo·메모·키 반복·모의 정지·단일 종료·기록·기존 완료 보존을 검사한다. 용량과 검증 결과는 [SIZE.md](SIZE.md), [QUALITY-v0.6.md](QUALITY-v0.6.md)에 기록한다.
