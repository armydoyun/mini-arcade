# MINI ARCADE v0.3 · 검토 반영과 검증

기준: 2026-11-01에 검토한 업로드 소스 ZIP의 v0.2 PC ESM 버전. 게임별 진입 모듈과 순수 HTML/CSS/JS 구조를 유지하며 공통 동작과 실제로 재현한 문제를 수정했다. 모바일·AI·네트워크 대전·번들러는 추가하지 않았다.

## 게임 그림·공통 SVG

28개 그림을 같은 140×112 필드에서 재구성하고 구조선의 불투명도, 둥근 모서리, 선 굵기, 기호·말의 크기를 맞췄다. 메인 M 마크와 파비콘도 같은 경로를 사용한다. 게임 고유 색을 유지하고 로컬 대전의 P1/P2는 코럴/블루로 일관되게 표현한다.

| 묶음 | 조정한 표현 |
|---|---|
| 테트리스·스네이크·벽돌 2종·플래피 | 블록 크기·다음 블록, 연결된 몸통, 공·궤적·패들, 틈과 새의 비례 |
| 2048·지뢰·로직·슬라이딩·Lights·Flood | 숫자·깃발·단순 격자와 실제 게임을 구별하는 상태·색상 |
| Stack·Dodge·Asteroids·Invaders·Catch·Runner | 층·위험 예고·우주선·적·수집물·이동 방향을 단순 도형으로 통일 |
| Memory·Simon·Maze | 카드 앞뒷면, 밝은 패드의 어두운 숫자, 벽과 출구의 선 굵기 |
| 틱택토·오목·사목·오델로 | 오목 다섯 돌과 광학 중심, 아래 돌이 받치는 사목 대각선, 오델로 칸 중앙의 돌 |
| 점과 상자·헥스·Pong·Cycles | 선/소유 상자, 동일 기하의 목표선, 선수 색·진행 방향 |
| 공통 도구 | 설정·검색·집중·하트·재시작·닫기·새 문제·뒤로·결과·재생·정지·화살표 |

실제 SVG를 한 화면에 놓고 비교했으며 그림 28개+공통 아이콘 13개의 XML 구조를 검사했다. 로고는 게임판의 축소 복제보다 게임을 구분하는 표식으로 사용한다.

## 검사 결과

환경: Node 24.22.1, Chrome PC 화면. 외부 테스트 패키지는 사용하지 않았다.

| 검사 | 통과 조건 수 | 범위 |
|---|---:|---|
| tests/rules.mjs | 9,890 | 병합·연결·뒤집기·충돌·회전·퍼즐 유일해·해답·경로 |
| tests/runtime.mjs | 724 | 28종 실제 모듈의 시작·진행·일시정지·승패·수 복원·종료·정리·앱 연동 |
| tests/regressions.mjs | 268 | 이번 수정의 프레임·입력·저장·기하·종료 경계 |
| 합계 | 10,882 | 조건 수이며 독립적인 게임 플레이 횟수는 아님 |

실행 검사에서는 4,698,374회 Canvas 호출의 수치가 유한한지 확인했다. 테트리스는 알려진 J/L/I 배치로 한 줄을 지우고 드롭+줄 점수 210점을 확인하며, 홀드 1회 제한과 바닥 잠금을 실제 키 입력으로 확인한다. 미로는 그려진 벽을 읽어 경로를 이동하고 우회 시의 효율 점수를 확인한다.

브라우저 확인:

- 1280×720: 테트리스를 포함한 28종 진입, 게임판·HUD·안내·도구 배치. 측정한 게임 패널의 하단은 720px 안에 들어왔다.
- 1024×768: 지뢰 24×16, 메모리 20장, 헥스 9×9. 960×720: 헥스의 육각 비례·목표선·가로 넘침 없음.
- 홈 카드 노출, 게임 선택, 같은 문제 재시작과 새 문제 생성, 모드 변경 취소/적용, 목록 이동 취소.
- 준비·일시정지 중 카드 답 숨김, 집중 모드 클릭 후 F 복귀, 사목 키보드 착지 미리보기·열 버튼 승리 후 결과 포커스.
- 결과 보드에서 실제 키보드로 탐색·입력 차단·결과 복귀, 로직 퍼즐 마지막 포인터 완료 시 다음 문제 포커스, 다음 미완료 이동·완료 집계.
- 28종 게임 그림과 공통 아이콘의 정렬·가독성·선/면 표현 비교.

원격 브라우저의 긴 렌더링 중단에서는 자동 일시정지가 작동했다. 검사 중 이를 계속하기로 풀어 확인했으며, 중단 시간을 플레이 시간에 더하지 않는 설계와 일치한다.

## 범위와 남은 실기 검증

로직 퍼즐은 5×5 입문 24개를 유지했다. 완료 추적과 난도 표시는 반영했지만 10×10·15×15 콘텐츠를 새로 작성하지 않았다. 더 큰 문제는 유일해와 단서만으로 풀리는 난도를 별도로 검증해야 한다.

Catch는 무작위 별을 모두 받을 수 없는 상황이 즉시 강제 생명 손실이 되는 문제를 규칙 변경으로 해결했다. 모든 별을 받도록 스케줄링하는 생성기는 추가하지 않았다. 운에 따라 콤보·점수 기회가 달라지는 구조는 유지하며 장시간 밸런스 표본은 별도다.

2048은 병합 팝과 생성 효과를 보완했다. 타일 전체가 좌표 사이를 이동하는 애니메이션 시스템은 추가하지 않았다. 종료 이펙트도 게임 규칙과 분리한 짧은 잔상 범위다.

브라우저 배치·입력 확인은 자동 DOM 검사와 구분한다. 스크린리더 실기, 여러 브라우저·확대율·DPR, 두 사람의 물리 키보드 고스팅, 장시간 난이도와 점수 분포는 이 검사로 보증하지 않는다. 사용자가 만든 최종 단일 HTML은 별도 산출물이므로 실행·외부 요청·용량을 다시 확인해야 한다.
