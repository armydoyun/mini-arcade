# MINI ARCADE · v0.7.0 · SOLO VS COMPUTER · ESM · PC

PC 브라우저에서 즐기는 40종의 작은 게임입니다. 혼자 하기 33종, 둘이 하기 13종이며 **미니 골프와 컴퓨터 상대 모드가 있는 5종은 두 인원 필터에 모두 포함**됩니다. 2인 모드는 한 기기를 공유하는 대전 또는 협동입니다. 실행 코드는 순수 HTML·CSS·JavaScript와 네이티브 ES Module로 구성합니다. 외부 라이브러리, CDN, 이미지, 폰트, 음원, 서버 API, npm 설치와 빌드 과정에 의존하지 않습니다.

## 실행

PC 키보드와 마우스를 사용하며, 960px 이상 너비를 기준으로 합니다. 모바일 레이아웃과 가상 방향키는 포함하지 않습니다.

사용 중인 로컬 정적 서버에서 `index.html`을 여세요. Python이 설치되어 있다면 프로젝트 폴더에서 다음과 같이 실행할 수 있습니다.

```sh
python -m http.server 8000
```

브라우저에서 `http://localhost:8000`에 접속합니다. 서버는 정적 파일만 제공하며 모든 게임 처리는 브라우저 안에서 이루어집니다. 외부 인터넷 연결은 필요하지 않습니다.

개발 소스를 `file://`로 직접 열면 브라우저의 모듈 보안 제한에 걸릴 수 있습니다. 더블클릭으로 여는 한 파일짜리 배포본은 `npm run build`가 `deploy/index.html`로 만듭니다(아래 ‘빌드와 CI/CD’). Node가 있으면 `npm run serve`로도 개발 서버를 띄울 수 있습니다.

## v0.7 · 혼자서도 하는 대전

둘이 있어야만 할 수 있던 대전 다섯 종에 **혼자 · 컴퓨터와** 모드를 추가했습니다. 플레이 모드에서 고르며, 홈의 ‘혼자 하기’ 필터에서 들어가면 처음에는 컴퓨터 모드로 열립니다.

| 게임 | 컴퓨터 상대 |
|---|---|
| 틱택토 | 완전 탐색(minimax). 가끔 실수해 이길 틈을 남기지만 즉시 승리·방어는 놓치지 않음. 역전 규칙 모드도 지원 |
| 사목 | 4칸 창 평가 + 알파-베타 5수 탐색 |
| 오목 | 네 방향 연결 길이·열린 끝 점수로 공격과 수비를 함께 판단 |
| 오델로 | 모서리 우대 자리 가중치 + 이동 가능 수, 3수 탐색 |
| Pong | 벽 반사까지 착지점을 예측하되 랠리마다 조준 오차와 반응 지연을 둠. W/S·↑/↓ 모두 내 패들 |

사람이 먼저 두고 컴퓨터는 약 0.5초 뒤 응수합니다. 생각하는 동안의 입력은 막고, 되돌리기는 컴퓨터의 응수까지 함께 되돌립니다. HUD·결과·기록은 ‘나 / 컴퓨터’ 승수로 표시하며, 기존 둘이 모드의 기록은 그대로 이어집니다. 계산은 순수 함수 `js/ai.js`에 있고 한 수에 수십 ms 이내입니다. `tests/ai.mjs`가 즉시 승리·방어, 무작위 상대와의 승률(틱택토 무패, 사목·오델로·오목 대부분 승리), 실제 모듈의 응수·입력 차단·되돌리기·종료를 검사합니다.

이번에는 레이저 반사 퍼즐·만칼라·스도쿠·파이프 연결을 추가했습니다. 폭탄 미로 대전·연쇄 낙하 퍼즐·배구·핀볼은 실시간 조작·물리·대전 밸런스 검증을 더 확보한 후로 보류했습니다.

| 게임 | 구성과 조작 |
|---|---|
| 레이저 반사 퍼즐 | 12판. 거울 클릭 / Space 회전, 분광기, 다중 목표. 모든 거울 배치를 전수 검사해 유일해·최소 회전을 확인 |
| 만칼라 | 로컬 2인 칼라 규칙. 48개/36개 씨앗 모드, 자기 줄 왼쪽부터 숫자 1~6, 추가 턴·포획·종료 정산·배분 애니메이션·공동 Undo |
| 스도쿠 | 18문제. 고정 숫자 42·34·28개 각 6문제, 모두 유일해. 숫자 입력, N 메모, Del/0 삭제, 관련 칸·중복 표시, 자동 메모 정리, 풀이 시간 기록 |

새 네 게임은 홈 첫 줄과 ‘새 게임 4’ 필터에서 찾습니다. 같은 도형 체계의 SVG 4개를 추가했습니다. 만칼라 로고는 실제와 같은 6칸씩 두 줄, 스도쿠는 9×9/3×3 구조, 레이저는 거울 각도와 빛의 꺾임을 맞췄습니다.

신규 퍼즐의 되돌리기는 자유롭게 사용하며 **힌트만 연습 기록**으로 구분합니다. 레이저·파이프는 회전 수, 스도쿠는 첫 편집부터의 풀이 시간을 낮을수록 좋게 비교합니다. 퍼즐 42개는 완료·보조 완료·다음 미완료 이동을 지원합니다. 만칼라는 모드별 승패 기록입니다.

새 네 게임은 그리기 빈도가 낮아져도 생각 중인 판의 입력을 막지 않도록 별도의 정지 정책을 사용합니다. 사용자 일시정지·포커스 상실·페이지 숨김은 계속 처리합니다. 실시간 게임과 메모리 미리보기 등 기존 게임의 긴 프레임 중단 보호는 유지합니다.

실제 브라우저에서 레이저·파이프·스도쿠 첫 판의 완주와 기록, 만칼라 추가 턴·씨앗 배분·Undo를 확인했습니다. 추가한 전체 고정 퍼즐은 자동 검사에서도 전부 실제 입력으로 완주했습니다. 범위와 검증 한계는 [docs/QUALITY-v0.6.md](docs/QUALITY-v0.6.md)에 있습니다.

## v0.3에서 이어받은 개선

- 홈 소개를 줄이고 게임 선택을 앞당겼습니다. 게임판은 남은 PC 창 높이를 기준으로 크기를 정하며, 큰 보드와 결과창도 같은 영역을 사용합니다.
- 물리·예약 작업·기록 시간을 하나의 활성 시계로 통일했습니다. 낮은 프레임 속도에서도 시간을 버리지 않고 나누어 진행하며, 0.75초를 넘는 프레임 중단은 자동 일시정지합니다. 준비·일시정지·라운드 대기는 기록 시간에서 제외합니다.
- 테트리스 착지 리셋 제한, 스프린트 타이머, Pong의 정지 패들 스핀, 미로의 동시 방향 입력을 수정했습니다.
- 메모리 카드 미리보기는 시작 후에만 진행하고 일시정지 중 답을 숨깁니다. Catch는 마우스와 키보드 속도를 맞추고 놓친 별은 콤보만 잃도록 조정했습니다.
- 시드 퍼즐은 같은 문제 재도전과 새 문제를 구분합니다. 슬라이딩·Flood 기록은 문제별, Lights Out은 최적해 대비 초과 이동, 미로는 경로 효율로 비교합니다.
- 네모네모 로직은 완료·보조 완료 표시, 완료 개수, 다음 미완료 문제 이동을 제공합니다. 기존 5×5 입문 24문제는 유지합니다.
- 저장 실패·손상된 개별 기록을 처리하고, 결과 기본 버튼·보드 탐색·키보드 포커스·숫자 대비를 보완했습니다.
- 28개 게임 SVG와 공통 아이콘을 같은 도형 체계로 정리했습니다. 헥스 로고와 실제 판은 셀·목표선 좌표를 공유합니다.

상세 변경과 기존 검토 R01~R28의 대응은 [docs/QUALITY-v0.3.md](docs/QUALITY-v0.3.md)에 있습니다. 이전 개선 이력은 [docs/QUALITY-v0.2.md](docs/QUALITY-v0.2.md)를 참고하세요.

기록·설정은 해당 브라우저의 `localStorage`에 저장합니다. 저장이 차단되면 ‘이번 실행 중’ 기록임을 표시하고 플레이를 계속합니다. 소코반·v0.6 신규 퍼즐의 자유 Undo를 제외한 싱글플레이 보조는 연습으로 구분하며 최고 기록을 갱신하지 않습니다. 변경된 시간·점수 체계의 기록은 `:v3:` 키로 분리하고 이전 데이터는 보관합니다. 이전 로직 퍼즐 완료 기록은 완료 표시에 반영합니다.

```text
js/connection-game.js  틱택토·오목·사목의 공통 배치·수 복원·컴퓨터 응수
js/ai.js               컴퓨터 상대: 틱택토·사목·오목·오델로의 수 선택
js/games/*.js          게임별 독립 ES Module
tests/*.mjs            개발 검증. 게임 실행에는 불필요
docs/                  변경·개발 기준·바이트 집계
```

게임 진입점은 `export default (session) => { ... }`입니다. 런타임은 HTML 1개, CSS 1개, JavaScript 49개입니다. 지연 `import()` 없이 모두 정적으로 연결하므로 `js/app.js`를 번들 진입점으로 사용합니다. 이미지·폰트 등의 추가 자산은 없습니다.

## 빌드와 CI/CD

게임 실행에는 여전히 아무 의존성도 없습니다. `package.json`의 개발 도구(esbuild·ESLint·Playwright)는 빌드와 검사에만 씁니다.

```sh
npm ci                 # 개발 도구 설치
npm run build          # deploy/index.html: CSS·JS를 모두 인라인한 단일 파일(file://로 열림)
npm run lint           # ESLint, 경고도 실패
npm run size:check     # 실행 원본 합계 1,000,000 B 미만
npm run test:node      # 모의 DOM 검사 + 빌드 검사
npm run test:browser   # Chromium에서 개발 소스와 배포본으로 40종을 실제 실행(npx playwright install chromium 필요)
npm test               # 전체
```

| 파일 | 역할 |
|---|---|
| `tools/build.mjs` | esbuild로 `js/app.js`를 IIFE로 묶고 CSS와 함께 `index.html`에 넣음. 스크립트는 `</body>` 앞으로 옮김 |
| `tools/inline-html.mjs` | 인라인 치환과 바깥 파일 참조·`</script` 안전 검사 |
| `tools/size.mjs` · `tools/serve.mjs` | 실행 원본 용량 집계 · 개발용 정적 서버 |
| `tests/run.mjs` | node / browser 묶음 실행기. `--strict`는 건너뛴 묶음도 실패로 처리 |
| `tests/browser/smoke.mjs` | 홈 카드·검색·필터, 40종 시작·입력·일시정지·재시작·복귀를 개발 소스와 배포본에서 검사. 콘솔 오류가 하나라도 있으면 실패 |
| `.github/workflows/ci.yml` | push·PR마다 lint → test(node, browser) → build. 배포본을 Artifacts에 올림 |

**GitHub Pages 자동 배포**: Settings → Pages → Source를 *GitHub Actions*로 바꾸고, Settings → Secrets and variables → Actions → Variables에 `DEPLOY_PAGES` = `true`를 추가하면 `main`에 push될 때마다 검사를 통과한 배포본이 Pages에 올라갑니다.

## 검증

Node 22·24에서 다음 검사를 통과합니다. 아래 node 검사는 외부 패키지 없이 실행하며(`npm run test:node`로 한 번에 실행), Node는 게임 실행에 필요하지 않습니다.

```sh
node tests/rules.mjs
node tests/runtime.mjs
node tests/regressions.mjs
node tests/new-games.mjs
node tests/expansion.mjs
node tests/logic-pack.mjs
node tests/ai.mjs
node tests/build.mjs
```

- 규칙 9,890개, 수명주기·통합 1,075개, 기존 회귀 268개, v0.4 게임 913개, v0.5 확장 235개, v0.6 로직 1,791개: 합계 **14,172개 검사 조건** 통과.
- 수명주기 검사는 40종 실제 모듈을 사용하며 5,705,487회 Canvas 호출의 수치가 유한한지 확인했습니다.
- 소코반 20개는 별도 최소 밀기 탐색과 실제 키 입력 완주를 모두 확인했습니다. 블록 완전 제거·복원, 장벽 규칙·완주, 탄환 반사·재장전·동시 격파·자기 피격·3승 종료를 실제 모듈에서 검사합니다.
- 탱크는 60/30/15/10fps로 **모의 프레임 간격을 바꿨을 때** 활성 시간과 이동 위치가 같음을 확인합니다.
- 버블은 조준 입력 21회로 전체 제거, 땅따먹기는 목표 점령과 생명 소진, 협동은 12개 풀이의 키보드·마우스 재생, 골프는 솔로·2인 9홀 전체 입력을 확인했습니다.
- 스도쿠는 별도 집합 기반 풀이, 파이프는 별도 제약 탐색, 레이저는 벡터 기반 광선 모델, 만칼라는 별도 순환 순서 모델과 교차 검사합니다. 신규 퍼즐 42개를 전부 입력으로 완주하며 만칼라 전체 경기·씨앗 보존·Undo·정산도 검사합니다.
- Chrome에서 카드·인원 필터·모드·준비/일시정지, 960×720·1024×768·1280×720·1920×1080 PC 배치를 확인했습니다. 게임 SVG 40개와 공통 아이콘 13개가 올바른 XML인지 검사했습니다.

현재 검증 브라우저는 별도 측정 화면에서도 RAF가 약 1fps로 관측되어, 60fps에서의 애니메이션 체감과 실시간 대전을 검증하지 못했습니다. 화면 확인과 자동 모의 프레임 검사를 구분합니다. 여러 PC·브라우저의 장시간 밸런스, 물리 키보드의 동시 입력도 추가 실기 확인 대상입니다.
